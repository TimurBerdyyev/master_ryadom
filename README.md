# Мастер рядом

Сервис поиска мастеров (сантехники, электрики, ремонт и т.д.): клиент без регистрации оставляет заявку,
проверенные мастера его города присылают предложения за 20 минут — или сервис сам находит мастера.

MVP: backend на FastAPI + PostgreSQL, простой веб-клиент вместо мобильного приложения/бота
(контакт с мастером — звонок или WhatsApp, см. ТЗ п.9).

Интерфейс доступен на трёх языках — русском, кыргызском и английском (переключатель в шапке сайта).

## Клиенты без регистрации, мастера — по договору

- Клиенту аккаунт не нужен: он видит мастеров с телефонами (звонок/WhatsApp) или оставляет заявку с именем
  и телефоном. В ответ — личная ссылка на заявку (предложения, выбор мастера, отзыв, жалоба); ссылки
  запоминаются в браузере в разделе «Мои заявки».
- Регистрируются только мастера. При регистрации мастер принимает договор (`/master-agreement.html`):
  отвечать на каждую заявку за 20 минут — иначе штраф и снижение рейтинга. Мастер загружает своё фото.
- «Гарантия сервиса»: в поиске и в рассылке заявок только мастера, которых админ отметил проверенными
  (выключается `MASTERS_REQUIRE_VERIFICATION=false`).
- Пропуски фиксируются автоматически раз в минуту; админ видит заявки без ответа (звонит клиенту сам)
  и нарушения с штрафами — «Админка → Без ответа». Сроки и суммы — `RESPONSE_MINUTES`, `MISSED_REQUEST_FINE`,
  `MISSED_REQUEST_RATING_PENALTY`. Текст договора — черновик, перед запуском его должен проверить юрист.

## Структура проекта

```
backend/   FastAPI-приложение, модели БД, JWT-авторизация
web/       Статический веб-клиент (HTML/CSS/JS без сборки)
scripts/   dev.sh — локальный запуск, test.sh — тесты и аудит зависимостей
deploy/    nginx.conf — веб-клиент + прокси /api → backend (для docker-compose)
docker-compose.yml
```

## Быстрый старт (локально, без Docker)

```bash
./scripts/dev.sh     # создаст .venv при первом запуске; API :8000 + сайт :8080, БД — SQLite (backend/local.db)
./scripts/test.sh    # автотесты + проверка зависимостей на известные уязвимости
```

Сайт: http://localhost:8080, документация API: http://localhost:8000/docs.
Веб-сервер в `dev.sh` отключает кеш браузера, так что правки HTML/CSS/JS видны после обычного обновления страницы.

## Запуск через Docker (рекомендуется)

```bash
cp .env.example .env               # секреты для docker-compose (JWT, CORS, пароль БД)
cp backend/.env.example backend/.env   # нужен только для запуска backend вне Docker
docker compose up --build
```

**Перед деплоем на реальный сервер обязательно замени значения в корневом `.env`:**

```bash
python3 -c "import secrets; print(secrets.token_urlsafe(48))"   # -> JWT_SECRET
```

И выстави `CORS_ORIGINS` в свой домен (например `https://master-ryadom.kg`) вместо `*`.
Без своего `JWT_SECRET` сервис стартует (чтобы не блокировать локальную разработку),
но пишет явное предупреждение в лог — и это небезопасно для продакшена: с дефолтным
секретом токен может подделать кто угодно, кто читал этот репозиторий.

- Веб-клиент: http://localhost:8080, API для него — через nginx по адресу http://localhost:8080/api/
- Напрямую API (и `/docs`) слушает только `127.0.0.1:8000` — с других машин он недоступен,
  весь внешний трафик идёт через nginx (`deploy/nginx.conf`)

При старте backend сам создаёт таблицы и заполняет список категорий услуг.

### Создание администратора

Публичная регистрация не позволяет получить роль `admin` (только `client`/`master`).
Первого администратора создают из контейнера backend/локально:

```bash
docker compose exec backend python -m app.create_admin "+996700000099" "пароль" "Имя"
# или локально из backend/: python -m app.create_admin "+996700000099" "пароль" "Имя"
```

Админ-панель — `web/admin/index.html` (вкладки: дашборд, пользователи, мастера, заказы, жалобы, категории).

## Запуск backend локально без Docker

```bash
cd backend
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env  # укажите свою строку подключения к PostgreSQL
uvicorn app.main:app --reload
```

Веб-клиент можно открыть просто как статические файлы (`web/index.html`) —
он сам определяет `http://localhost:8000` как адрес API при локальном запуске.

## Регистрация по email и уведомления мастерам

- Email обязателен для мастеров и подтверждается кодом из письма; восстановление пароля — тоже по email.
  Войти можно по телефону или по email.
- Мастер при регистрации сам решает, получать ли уведомления о новых заказах, и выбирает канал — Email, Telegram
  или SMS (по умолчанию выключено; меняется в профиле). SMS и Telegram показаны как «Скоро», пока не подключены.
- Пока почта не настроена (`EMAIL_PROVIDER=console`), письма не уходят: код пишется в лог сервера и подсказывается
  на странице — так можно регистрироваться при локальной разработке. Настройка почты и бота — `DEPLOY.md`.

Пошаговая инструкция — [DEPLOY.md](DEPLOY.md). Самый простой способ для проверки — **Render**:

## Платный тариф для мастеров

Готов, но **выключен** (`SUBSCRIPTIONS_ENABLED=false`) — до запуска мастера пользуются сервисом бесплатно.
При включении: первый месяц бесплатно, дальше подписка на 1/3/6/12 месяцев (скидки 0/10/15/25%),
цена задаётся `SUBSCRIPTION_PRICE`. Без подписки мастер не видит новые заказы, не может откликаться
и скрыт из поиска. Пока платёжная система не подключена, оплаты подтверждает администратор
(вкладка «Подписки» в админке); подключение эквайринга описано в `backend/app/payments.py`.

Посмотреть локально, как это выглядит включённым:

```bash
cd backend && SUBSCRIPTIONS_ENABLED=true DATABASE_URL=sqlite:///./local.db ../.venv/bin/uvicorn app.main:app --reload
```

## Тесты

```bash
cd backend
pip install -r requirements-dev.txt
python -m pytest tests -q
```

Тесты используют временную SQLite-базу и проверяют весь сценарий заказа, а также попытки взлома:
IDOR, подделку JWT, SQL-инъекции в поиске, загрузку HTML под видом картинки, повышение роли до admin,
перебор паролей.

## Основные сущности (раздел 13 ТЗ)

`users`, `masters`, `categories`, `services`, `orders`, `order_offers`, `reviews`,
`messages`, `photos`, `addresses`, `working_hours`, `notifications`, `payments`, `complaints`.

## Реализованные API-эндпоинты

- `POST /auth/register`, `POST /auth/login`, `GET /auth/me`
- `GET /categories`
- `GET /masters` (фильтры: category_id, city, verified, min_rating, lat/lon), `GET /masters/{id}` —
  доступны без авторизации, но телефон мастера (`user.phone`) виден только вошедшим пользователям
- `GET /masters/me`, `PATCH /masters/me` — просмотр и редактирование своего профиля (только для роли `master`)
- `POST /masters/me/services`, `DELETE /masters/me/services/{id}` — свои услуги и цены
- `POST /orders`, `GET /orders`, `GET /orders/{id}`
- `POST /orders/{id}/offer` — мастер предлагает цену
- `POST /orders/{id}/accept` — клиент выбирает предложение
- `POST /orders/{id}/cancel`
- `POST /orders/{id}/review`, `GET /masters/{id}/reviews`
- `GET /orders/feed` — открытые заказы в категориях услуг мастера (без адреса и данных клиента)
- `GET /orders/{id}/offers` — предложения по заказу (клиент видит все, мастер — только своё)
- `POST /orders/{id}/status` — мастер двигает статус вперёд (подтвердил → в пути → в работе → выполнен),
  клиент может подтвердить выполнение
- `GET /notifications`, `GET /notifications/unread-count`, `POST /notifications/read-all`
- Телефоны клиента и мастера открываются друг другу только после выбора мастера (`client_contact` / `master_contact`)
- `POST /complaints` — подать жалобу (на пользователя и/или заказ)
- `GET /admin/stats` — пользователи/мастера/заказы/оборот/комиссия (раздел 12 ТЗ)
- `GET/PATCH /admin/users`, `GET/PATCH /admin/masters` (подтверждение мастера),
  `GET /admin/orders`, `GET/PATCH /admin/complaints`, `POST/DELETE /admin/categories`
  — всё только для роли `admin` (см. `python -m app.create_admin`)
- `POST /orders/{id}/photos`, `DELETE /orders/{id}/photos/{photo_id}` — фото к заказу (до 5 шт.)
- `POST /masters/me/photos`, `DELETE /masters/me/photos/{photo_id}` — фото работ мастера (до 20 шт.)
  Файлы отдаются статикой по `/uploads/...`; допустимы только JPEG/PNG/WebP, лимит размера —
  `MAX_UPLOAD_SIZE_MB` (по умолчанию 5 МБ). В Docker файлы живут в именованном томе `uploads_data`,
  так переживают пересборку контейнера.

## Защита от взлома

- **Пароли**: bcrypt с явным ограничением в 72 байта (требование самого bcrypt), минимум 6 символов
  на регистрации, валидируется схемой Pydantic.
- **JWT**: секрет обязателен к замене перед продакшеном (см. выше), иначе явное предупреждение в логах.
- **Блокировка**: заблокированный администратором пользователь не может ни войти, ни продолжить
  пользоваться уже выданным токеном (проверка на каждый авторизованный запрос).
- **Роль `admin`** нельзя получить через публичную регистрацию — только через
  `python -m app.create_admin` или повышением существующим админом в БД напрямую.
- **IDOR**: доступ к заказу (`GET /orders/{id}`) проверяется — только автор заказа, назначенный
  мастер или админ; все действия с заказами/услугами/фото проверяют владельца.
- **Rate limiting**: `/auth/login` и `/auth/register` ограничены 10 попытками за 10 минут с одного
  IP (простая in-memory реализация — для многопроцессного деплоя за балансировщиком переносить
  на Redis).
- **XSS**: все пользовательские данные (имена, описания, отзывы, жалобы, адреса) экранируются
  перед вставкой в DOM на фронтенде (`esc()` в `web/js/api.js`) — проверено ручными XSS-пробами
  через имя/описание/услугу, включая просмотр из под администратора.
- **Загрузка файлов**: белый список content-type (JPEG/PNG/WebP), лимит размера, лимит количества
  на заказ/мастера, случайные имена файлов на диске, проверка владельца на удаление.
- **Открытый редирект**: параметр `?next=` на входе/регистрации принимает только страницы этого сайта
  (`safeNext()` в `web/js/api.js`) — ссылки вида `?next=javascript:...` или `?next=https://чужой-сайт` игнорируются.
- **Загрузка файлов**: кроме content-type проверяется сигнатура файла (JPEG/PNG/WebP), файлы из `/uploads`
  отдаются с `nosniff` и `Content-Security-Policy: sandbox`.
- **Предложения мастеров**: только в категориях своих услуг, не на свой заказ, одно предложение на заказ
  (повторное — обновляет цену); мастера не видят цены конкурентов.
- **Заблокированные** пользователи и мастера скрыты из поиска и не видят телефонов.
- **Docker**: Postgres, Redis и сам backend слушают только `127.0.0.1`; снаружи доступен только nginx.
  nginx перезаписывает `X-Forwarded-For`, а uvicorn запущен с `--proxy-headers` — лимит попыток входа
  считается по настоящему IP клиента, и подделать его заголовком нельзя.
- **Зависимости**: `./scripts/test.sh` запускает `pip-audit`; на момент последней проверки известных уязвимостей нет.
- **CORS**: настраивается через `CORS_ORIGINS` (по умолчанию `*` для разработки — сузить на проде).
